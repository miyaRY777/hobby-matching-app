# タグカード復元system spec修正 設計書

## 背景

PR #289でタグ説明文入力欄を初期表示するよう変更した結果、上限超過の11件を復元するsystem specでは後方のタグカードが画面外へ出るようになった。

復元処理は成功しており、「ゲーム」と説明開閉ボタンはDOM上に存在する。しかし、既存テストの `have_text("ゲーム")` は可視テキストだけを対象とするため失敗する。

## 目的

バリデーションエラー後にタグカードが復元されることを、画面サイズやスクロール位置に依存せず検証する。

## 変更範囲

- `spec/system/my/profile_tag_autocomplete_spec.rb` の復元テストだけを変更する。
- アプリケーションコード、DB、公開APIは変更しない。
- 既存の未追跡ファイルや無関係なテストは変更しない。

## 修正方針

「ゲーム」の確認を、可視領域だけでなく非表示・画面外のDOM要素も対象にするCSSセレクターの検証へ変更する。

タグカードを表す要素に対して `text: "ゲーム"` と `visible: :all` を指定し、単なるページ内文字列ではなく、復元されたカード内にタグ名が存在することを確認する。

画面スクロールによる確認は、ビューポートサイズに依存して不安定になるため採用しない。11件すべての個別検証は、このテストの関心である「カード復元」の確認には過剰なため採用しない。

## テスト方針

1. RED: 現在の対象system specを実行し、可視テキスト判定で失敗することを確認する。
2. GREEN: DOM上のタグカードを確認する最小変更を行い、対象system specを成功させる。
3. REFACTOR: 追加の整理が不要であることを確認する。
4. 全RSpecを実行する。
5. 変更したRSpecファイルのRuboCopと `git diff --check` を実行する。

## 受入条件

- バリデーションエラー後に「ゲーム」のタグカードがDOM上へ復元されることを検証できる。
- 対象system specが成功する。
- 全RSpecが成功する。
- 変更したRSpecファイルのRuboCopが成功する。
