# タグ説明欄を初期表示で開く設計

## 関連 Issue

- GitHub Issue: #288「プロフィール編集のタグ説明欄を初期表示で開く」

## 背景

プロフィール編集では趣味タグを登録する利用者はいる一方、タグの説明までは入力されないことが多い。現在の説明欄は初期状態で閉じており、説明を入力できることに気づきにくい。

## 目的

タグの登録直後から説明入力欄を見える状態にし、タグだけでなく、その趣味の楽しみ方や経験も入力してもらいやすくする。

## 仕様

- プロフィール編集画面に復元された既存タグは、説明の有無にかかわらず説明欄を開いて表示する。
- 新しく追加したタグも、説明欄を開いて表示する。
- 開いている状態のボタン文言は「説明を閉じる」とする。
- 閉じている状態のボタン文言は「説明を開く」とする。
- ボタンを押すたびに説明欄の表示状態とボタン文言を同時に切り替える。
- 説明欄を閉じても入力値は保持し、フォーム送信時に従来どおり保存する。
- 説明文は引き続き任意入力とする。

## 実装範囲

### Stimulus コントローラ

`app/javascript/controllers/tag_description_controller.js` が生成するタグカードについて、説明欄の初期 `hidden` を外す。開閉処理では、対象カードの表示状態を切り替えた後、その状態に対応するボタン文言へ更新する。

### システムスペック

`spec/system/my/profile_tag_description_spec.rb` を更新し、次を確認する。

- 新規タグ追加直後に説明欄が表示される。
- 既存タグの復元直後に説明欄が表示される。
- 初期ボタン文言が「説明を閉じる」である。
- 一度押すと説明欄が閉じ、文言が「説明を開く」になる。
- もう一度押すと説明欄が開き、文言が「説明を閉じる」に戻る。
- 説明の保存とタグ削除に既存の回帰がない。

## データフロー

タグ一覧が変更されると、`tag-autocomplete` から `chips-changed` イベントが送られ、`tag-description` がタグカードを再描画する。各カードは説明欄が開いた状態で生成される。利用者が開閉ボタンを押した場合だけ、そのカード内の説明欄とボタン文言を切り替える。入力内容は従来どおり `tag-description-update` イベントを介して hidden field に反映される。

## エラー処理

開閉対象の説明欄が見つからない場合は、現行動作と同様に処理を終了し、他のカードや入力値へ影響を与えない。

## 対象外

- DB、モデル、保存サービスの変更
- 説明文の必須化
- 文字数上限の変更
- タグカード全体のデザイン変更
- プロフィール表示画面のタグ開閉動作の変更

## 検証方針

- 対象システムスペックを RED、GREEN の順で実行する。
- 関連するプロフィールタグのシステムスペックを実行する。
- RuboCop を実行する。
- 確認系コマンドは `docker compose exec web` 経由を優先する。
